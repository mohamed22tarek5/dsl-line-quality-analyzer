# 🔧 تحليل وفحص جودة خط الإنترنت DSL / VDSL — لأي شركة

> هل الإنترنت بطيء؟ هل الـ Ping غير مستقر؟ أو تريد معرفة الحالة الفعلية لخط DSL / VDSL ؟
>
> بدل الاعتماد على سرعة الإنترنت فقط، يمكنك استخراج بيانات الخط من الراوتر وإجراء فحص وتحليل فني شامل باستخدام هذا الـ Prompt.
>
> **الفكرة ببساطة:** انسخ ملف `prompt.md` إلى أي نموذج ذكاء اصطناعي (ChatGPT / Claude / Gemini / Copilot / DeepSeek)، ثم ارفع له **Screenshot من صفحة حالة DSL في الراوتر** أو الصق البيانات كنص، فيقوم بتحليل الخط كمهندس شبكات ويعطيك تقريراً كاملاً عن السرعة والاستقرار والأخطاء وإمكانية رفع السرعة.
>
> **الهدف:** ليس فقط أعلى رقم Sync، بل **أعلى سرعة عملية ومستقرة** يمكن لخطك دعمها بدون تقطيع أو إعادة اتصال متكررة.

## 🤔 هل تعاني من هذه المشاكل؟

- الإنترنت بطيء رغم أن الباقة كبيرة؟
- الـ Ping عالٍ أو غير مستقر في الألعاب؟
- لمبة DSL في الراوتر تفصل أو ترمش كثيراً؟
- تريد تعرف هل خطك يستحمل سرعة أعلى قبل ما تكلم الشركة؟
- الدعم الفني يقول "الخط تمام" وأنت ما زلت تعاني؟

**هذا المشروع لك.** يعطيك تحليل هندسي مبني على أرقام الراوتر الفعلية، لتتكلم مع الشركة بدليل تقني بدلاً من "النت بطيء".

لمن هذه الأداة؟

- **المستخدم المنزلي:** يريد فهم حالة خطه وهل يمكن رفع السرعة.
- **الفني / مهندس الشبكات:** يريد تقريراً منظماً وسريعاً لتشخيص خط العميل.
- **موظف الدعم الفني:** يريد تحديد هل المشكلة داخل المنزل أم خارجية أم إعدادات بورت.
- **أي شخص يتعامل مع ISP:** بدلاً من الشكوى العامة، تقول: "الخط يعمل على كذا، والقدرة المتاحة كذا، ومعدل الأخطاء كذا".

## 📌 كيف تحصل على بيانات الخط من الراوتر؟

1️⃣ افتح المتصفح واكتب:

```
192.168.1.1
```
> في بعض الراوترات قد يكون `192.168.0.1` أو `192.168.8.1` — تجده مكتوباً على ظهر الراوتر.

2️⃣ سجّل الدخول إلى الراوتر (اليوزر والباسورد غالباً على ظهر الجهاز).

3️⃣ ابحث عن:

```
DSL / xDSL / VDSL Status / Line Information / Broadband
```

4️⃣ ابحث عن بيانات مثل:

```
Sync Rate • SNR Margin • Attenuation • CRC • FEC • Uptime • Attainable Rate
```

5️⃣ التقط **Screenshot واضح** لبيانات الخط كاملة، بدون قص الأخطاء ومدة التشغيل (Uptime) لأنها مهمة جداً للتحليل.

**نصائح لصورة جيدة:**
- استخدم متصفح الكمبيوتر وليس تصوير الموبايل للشاشة.
- كبّر الصفحة (`Ctrl +`) قبل التصوير لتكون الأرقام واضحة.
- صوّر الجدول كاملاً Downstream و Upstream.
- لو الراوتر يعرض Downstream و Upstream في تبويبين، صوّر الاثنين.
- احرص على إخفاء: IP العام، اسم المستخدم وكلمة المرور، رقم الهاتف، عنوان MAC إن ظهروا في الصورة.

## 🔍 هذا ليس مجرد تقرير عادي

الـ Prompt مصمم ليكون **أداة فحص وتحليل فني شاملة لخط DSL / VDSL**، وليس مجرد تلخيص لأرقام الراوتر.

يقوم بتحليل وربط القراءات معاً، ثم يوضح:

🔹 القراءات الفعلية للخط بدقة
🔹 SNR & Attenuation وجودة الإشارة
🔹 CRC / FEC ومعدل الأخطاء
🔹 DSL Uptime واستقرار الاتصال
🔹 Current / Actual Rate & Attainable Rate
🔹 Headroom وإمكانية تجربة سرعة أعلى
🔹 المؤشرات والمشاكل التي تستحق التحقيق
🔹 الفرق بين Measurement / Calculation / Interpretation
🔹 نصائح عملية لاستكشاف وتحسين الخط
🔹 البيانات الناقصة التي تحتاج إلى فحص إضافي، **بدون افتراض قيم غير موجودة**

**الهدف ليس أن يقول لك "الخط جيد أو سيئ" فقط، بل أن يشرح القراءات، ويربط بينها، ويحدد ما الذي تدعمه البيانات فعلياً.**

المحلل يعمل كمهندس متخصص في:
- ADSL / ADSL2 / ADSL2+
- VDSL / VDSL2
- DSLAM / MSAN
- تشخيص خطوط xDSL
- تشخيص الأسلاك النحاسية (Copper Pair Diagnostics)
- تحسين إعدادات الراوتر / المودم
- تحسين Wi-Fi والشبكة المنزلية

ويحلل أكثر من 20 خاصية: DSL Mode, Profile, Current Rate, Attainable Rate, SNR Margin, Line Attenuation, Power, Data Path, Interleave Depth / Delay, INP, CRC, FEC, HEC, ES / SES, G.INP, Vectoring, Bitswap, SRA, DSL Uptime.

## ⚠️ Speedtest ≠ تشخيص خط DSL

`Speedtest` و `Fast.com` يختبران **سرعة الإنترنت الفعلية** التي تصل لجهازك، لكنهما **لا يكفيان وحدهما** لتشخيص جودة خط DSL.

أما بيانات الراوتر فتعطيك معلومات أعمق عن حالة اتصال DSL / VDSL، مثل جودة الإشارة، الأخطاء، معدل التزامن، والاستقرار.

| | Speedtest | بيانات الراوتر (DSL Status) |
|---|---|---|
| ماذا يقيس؟ | سرعة التحميل الفعلية + Ping | Sync + SNR + Attenuation + أخطاء + Uptime |
| يتأثر بـ Wi-Fi؟ | نعم جداً | لا |
| يكشف عطل السلك النحاسي؟ | لا | نعم |
| يكشف عدم استقرار الخط؟ | جزئياً | بدقة (CRC / ES / SES / Re-Sync) |
| يحدد إمكانية رفع السرعة؟ | لا | نعم (Attainable + Headroom) |

**القاعدة الذهبية:** قبل الحكم على DSL، جرّب جهازاً واحداً بكابل Ethernet مباشرة وبدون تحميلات أخرى، ثم قارن Speedtest مع Sync Rate.

## 🌐 هل يعمل مع أي شركة إنترنت؟

**نعم.** ويمكن استخدام هذا التحليل مع خطوط DSL / VDSL لدى شركات الإنترنت المختلفة، طالما أن الراوتر يعرض بيانات الخط المطلوبة.

يعمل سواء كنت على WE / فودافون / أورانج / اتصالات / STC / زين / Ooredoo أو أي مزود آخر — لأن التحليل يعتمد على **معايير تقنية عالمية لـ xDSL** وليس على نظام شركة معينة.

### الخطوة 3: جهّز بيانات الخط
اختر صورة (الأفضل) أو نص يدوي كما شرحنا بالأعلى.

### الخطوة 4: أرسل البيانات للمحلل
ارفع الصورة أو الصق النص في نفس المحادثة.

### الخطوة 5: اقرأ التقرير
ستحصل على:
1. **جدول تحليل الخط** (فقط للخصائص الظاهرة فعلاً)
2. **تفسير لكل قيمة** وربطها بباقي القراءات

لو طلب منك بيانات ناقصة (مثل Uptime أو ES / SES أو Speedtest أو قراءة في وقت مختلف)، أرسلها ليكمل التحليل بدقة.

**💡 نصيحة احترافية:** احتفظ بنسخة من قراءات خطك وهو مستقر (Screenshot + التاريخ). عند حدوث مشكلة لاحقاً، أرسل القراءتين القديمة والجديدة معاً للمحلل — المقارنة بينهما تكشف سبب التدهور بدقة أكبر بكثير من قراءة واحدة.

## 💡 مثال عملي للاستخدام

**أنت ترسل:**

> [صورة شاشة فيها]
> Current Rate Down: 40960 kbps
> Attainable Rate Down: 55000 kbps
> SNR Down: 9.2 dB
> Attenuation Down: 14.5 dB
> CRC Down: 120
> Uptime: 48 hours

**المحلل سيقوم تلقائياً بـ:**

```
نسبة الاستخدام = 40960 ÷ 55000 × 100 = 74.47%  (Calculation)
Headroom = 55000 − 40960 = 14040 kbps ≈ 14 Mbps  (Calculation)
CRC/hour = 120 ÷ 48 = 2.5 CRC/hour  (Calculation)
```

ثم يفسّر: السرعة الحالية أقل من القدرة المتاحة، الهامش موجود، معدل الأخطاء منخفض خلال 48 ساعة، الاستقرار جيد، ثم يعطي القرار: `يمكن تجربة سرعة أعلى` أو `السرعة الحالية مناسبة للاستقرار` مع السبب.

## 📊 ماذا ستحصل عليه؟ (مخرجات التحليل)

### 1. جدول تحليل الخط

| العمود | معناه |
|---|---|
| الخاصية | اسم الخاصية (SNR, Attenuation, CRC...) |
| التعريف البسيط | شرح مبسط لغير المتخصص |
| Download / Upload | القيمة لكل اتجاه |
| ماذا تعني القيمة في هذا الخط؟ | تفسير خاص بخطك أنت وليس كلاماً عاماً |
| الحساب / النتيجة | أي معادلة تم تطبيقها |
| التقييم | Excellent / Good / Acceptable / Needs Investigation |
| الدليل / الملاحظة | لماذا قيّمناها هكذا؟ |

> **ملاحظة:** الجدول يعرض فقط الصفوف التي ظهرت بياناتها فعلاً. لو خاصية غير موجودة في صورتك لن يتم اختراعها.

### 2. جدول الخلاصة النهائية

| البند | النتيجة |
|---|---|
| الحالة | مختصر حالة DSL |
| السرعة | Current مقابل Attainable |
| SNR | مختصر |
| Attenuation | مختصر (+ تقدير المسافة فقط إذا طلبت ذلك صراحة) |
| الأخطاء | CRC / FEC / HEC + معدل CRC في الساعة إن أمكن |
| الاستقرار | مختصر |
| إمكانية رفع السرعة | قرار واحد + السبب |
| أهم مشكلة محتملة | إن وجدت + الدليل |
| التحسين المقترح | أهم خطوة عملية تالية |
| ما لا يمكن إثباته | البيانات الناقصة |

### 3. القرار الفني النهائي (6 نقاط)

1. حالة DSL الحالية
2. هل توجد مؤشرات أخطاء؟
3. هل توجد مؤشرات عدم استقرار؟
4. هل توجد Headroom؟
5. هل توجد بيانات كافية لتجربة سرعة أعلى؟
6. ما أهم خطوة عملية تالية؟

## 📖 شرح أهم المصطلحات ببساطة

| المصطلح | معناه ببساطة | لماذا يهمك؟ |
|---|---|---|
| **DSL Mode** | التقنية المستخدمة (ADSL2+ أو VDSL2) | تحدد السرعة القصوى الممكنة |
| **Profile** | إعداد الاتصال من السنترال (مثل 17a في VDSL) | يحدد خصائص السرعة والترددات |
| **Current / Actual Rate (Sync)** | سرعة المزامنة بين الراوتر والسنترال | هي سرعة الخط الحقيقية، ليست سرعة التحميل في المتصفح |
| **Attainable Rate** | تقدير الراوتر لقدرة الخط الحالية | يوضح هل خطك يستطيع سرعة أعلى نظرياً |
| **SNR Margin** | هامش الأمان بين الإشارة والضوضاء (dB) | كلما قل قد تزيد السرعة لكن يقل الاستقرار |
| **Line Attenuation** | مقدار فقد الإشارة في السلك (dB) | كلما زاد يعني ظروف انتقال أصعب |
| **CRC** | أخطاء لم يتم تصحيحها | يجب ربطها بمدة التشغيل، وليس بالرقم وحده |
| **FEC** | أخطاء تم تصحيحها تلقائياً | وجودها وحده ليس دليل مشكلة |
| **ES / SES** | ثواني حدث فيها خطأ / خطأ شديد | أفضل مقياس للاستقرار عبر الزمن |
| **Interleaving / INP / G.INP** | آليات حماية من الأخطاء | تحسن الاستقرار مقابل زيادة بسيطة في التأخير (Ping) |
| **DSL Uptime** | مدة استمرار الاتصال بدون انقطاع | بدونها لا يمكن الحكم على الأخطاء |
| **Vectoring** | تقنية تقليل التداخل بين خطوط VDSL | تحسن الأداء عند تفعيلها من السنترال |
| **Speedtest** | سرعة الإنترنت الفعلية على جهازك | تتأثر بالـ Wi-Fi والضغط على الشبكة، وليست نفسها Sync |

**معادلات مهمة يحسبها المحلل لك:**
```
نسبة الاستخدام % = (Current ÷ Attainable) × 100
Headroom = Attainable − Current
CRC/hour = عدد CRC ÷ مدة التشغيل بالساعات
```

## ⚖️ قواعد التحليل الصارمة

هذه الأداة مصممة لتكون دقيقة وليست متفائلة. أهم القواعد التي يلتزم بها:

1. **لا تخمين:** أي قيمة غير ظاهرة لن يتم افتراضها.
2. **الصورة غير الواضحة:** سيكتب `غير واضحة — لا يمكن قراءتها بدقة من الصورة` ولن يخمّن الرقم.
3. **Speedtest ≠ Sync:** سرعة سبيد تست ليست سرعة المزامنة.
4. **لا حكم من رقم واحد:** لا يتم تقييم الخط من SNR وحده أو CRC وحده أو Attenuation وحده.
5. **CRC تُربط بالزمن:** 500 خطأ في ساعة واحدة مشكلة، لكن 500 خطأ في 30 يوم قد يكون طبيعياً.
6. **FEC وحده ليس مشكلة:** بل دليل أن نظام التصحيح يعمل.
7. **Attainable المرتفع ليس ضماناً:** هو تقدير من الراوتر تحت ظروف اللحظة، وليس وعداً من الشركة.
8. **لا اتهام للشركة بدون دليل:** لا يفترض أن المزود يحجب السرعة عمداً.
9. **لا تقدير للمسافة تلقائياً:** لن يحوّل dB إلى متر إلا إذا طلبت ذلك صراحة، وعندها سيوضح أنها `Estimate` فقط.
10. **التفريق الدائم بين:** `Measurement` = مقروءة مباشرة / `Calculation` = محسوبة رياضياً / `Estimate` = تقدير / `Interpretation` = تفسير هندسي.
11. **التسلسل دائماً:** `استخرج → تحقق → احسب → فسّر → اربط القراءات → قيّم → حدد الاحتمالات → اقترح الإجراء → لخّص`

## 🚀 تقييم إمكانية رفع السرعة

يوجد **3 قرارات فقط**، واحد منها سيظهر لك مع السبب:

| القرار | معناه |
|---|---|
| **يمكن تجربة سرعة أعلى** | يوجد Headroom + استقرار جيد + أخطاء منخفضة |
| **السرعة الحالية مناسبة للاستقرار** | الرفع الآن قد يسبب تقطيع أو أخطاء أو Re-Sync متكرر |
| **لا توجد بيانات كافية للحكم** | نحتاج Uptime أطول أو ES / SES أو قراءات إضافية |

**مخاطر رفع السرعة التي سيحذرك منها:**
انخفاض SNR Margin، زيادة CRC و ES / SES، انخفاض الاستقرار، زيادة إعادة الاتصال، تغير Data Path أو Interleaving حسب إعدادات الشبكة.

## 🔧 التحسينات المقترحة

### أولاً: التحسينات المادية (بالترتيب)

1. فحص كابل RJ11 والتأكد أنه سليم ومحكم
2. تجربة Splitter آخر (إذا كان نظامك يستخدم Splitter)
3. تجربة الراوتر مباشرة على الخط الرئيسي / نقطة الاختبار إن أمكن
4. تقليل طول كابل DSL الداخلي قدر الإمكان
5. إزالة تمديدات الهاتف غير الضرورية
6. فحص الوصلات والتوصيلات الداخلية
7. فحص البوكس الخارجي
8. طلب فحص الزوج النحاسي من الشركة
9. طلب فحص البورت / DSLAM
10. مراجعة السرعة / Profile مع مزود الخدمة عند الحاجة

### ثانياً: تحسين Wi-Fi (إذا كان DSL سليماً لكن الأجهزة بطيئة)

- استخدم `5GHz` للقريب و `2.4GHz` للبعيد
- اختر Channel غير مزدحم
- حدّث Firmware الراوتر من مصدر موثوق
- جرّب كابل Ethernet مباشرة لعزل مشكلة Wi-Fi عن DSL
- تغيير DNS **لا يرفع** سرعة DSL، بل قد يحسن فتح المواقع فقط

### ثالثاً: الأجهزة واستهلاك الإنترنت

افحص: الأجهزة المتصلة، التحميلات النشطة، تحديثات النظام، النسخ السحابي، البث، التورنت، التطبيقات في الخلفية. يمكن استخدام QoS لتوزيع السرعة لكنه **لا يزيد** سرعة الخط نفسه.

## ⚠️ ملاحظات وتنبيهات مهمة

- **العلاقة `1 dB = 72 m` ليست قياساً فعلياً للمسافة**، بل معادلة تقريبية جداً تتأثر بنوع النحاس وقطره والوصلات والترددات. لا تعتمد عليها لتحديد بعدك عن السنترال.
- **لا تغيّر SNR Target أو Profile يدوياً** إلا إذا كان الخيار موثقاً ومدعوماً من جهازك ومن مزود الخدمة.
- **لا تعتبر 70% قاعدة رسمية** لاستغلال الخط. المحلل يعرض النسبة كرقم فقط بدون الحكم بها وحدها.
- **G.INP و Vectoring و Interleaving** قد تكون إعدادات مقصودة للاستقرار وليست دليل عطل.
- **جودة الصورة = جودة التحليل.** صورة مهزوزة أو مقصوصة ستؤدي لتحليل ناقص.
- بيانات DSL (سرعة، SNR، أخطاء) ليست حساسة، لكن **أخفِ دائماً** IP العام وكلمات المرور وأرقام الهاتف.

## ❓ الأسئلة الشائعة FAQ

**س: هل أحتاج خبرة تقنية لاستخدام الأداة؟**
ج: لا. فقط انسخ البرومبت وأرسل الصورة واقرأ الخلاصة بالعربي المبسط.

**س: أي نموذج ذكاء اصطناعي أفضل؟**
ج: أي نموذج حديث يدعم تحليل الصور يعمل جيداً (GPT-4o / Claude 3.5 / Gemini 1.5 / DeepSeek / Copilot أو أحدث). كلما كان النموذج أقوى في قراءة الصور كان الاستخراج أدق.

**س: الراوتر لا يعرض Attainable Rate أو الأخطاء، هل التحليل سيعمل؟**
ج: نعم، سيحلل فقط القيم الظاهرة ويكتب لك ما هي البيانات الناقصة اللازمة للحكم (مثل Uptime أو ES).

**س: هل يمكن تحليل Speedtest فقط بدون بيانات الراوتر؟**
ج: يمكن تحليل Speedtest لكنه **لا يحدد جودة السلك النحاسي**. ستحتاج بيانات DSL للحكم على الخط نفسه.

**س: خطي VDSL والقراءات مختلفة عن ADSL، هل هذا طبيعي؟**
ج: نعم. كل تقنية لها ترددات وقيم طبيعية مختلفة. المحلل يراعي التقنية الظاهرة ولا يقارن VDSL بـ ADSL بنفس المعايير.

**س: هل أرسل بياناتي الخاصة؟ هل هي آمنة؟**
ج: بيانات DSL ليست حساسة. لكن احرص على **إخفاء**: عنوان IP العام، اسم المستخدم وكلمة المرور، رقم الهاتف، عنوان MAC، إذا ظهروا في الصورة.

**س: كم مرة يجب أن أفحص الخط؟**
ج: مرة بحالة طبيعية (للمقارنة)، ومرة وقت المشكلة، ويفضل قراءتان في وقتين مختلفين (صباحاً ومساءً) لاكتشاف التأثر بالضوضاء أو الضغط.

**س: هل يعمل مع أي شركة؟**
ج: نعم، طالما الراوتر يعرض بيانات الخط (Sync / SNR / Attenuation / CRC...). التحليل يعتمد على معايير xDSL العالمية.
